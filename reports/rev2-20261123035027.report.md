## 方法与证据强度

状态判定标准：页面必须同时满足下列条件才算“到达”，否则只记为尝试：

1. 页面 URL 属于维护方声明入口，`main[data-area]` 与计划模式一致；
2. `main[data-publication]` 与 `/release` 中该时刻的发版编号一致；
3. 可见文本、当前人群（原生选择器值）、报名表 `data-form`、帮助层 `data-component` 与计划匹配；
4. 焦点确实落在预期控件上（以浏览器可访问性树的 `focused` 节点为准，而不是凭文本猜测）。

证据强度分类（页面文本没读到、键盘路径进不到、当前资料不足以判断，三者互不替代）：

| 标记 | 含义 | 判据 |
| --- | --- | --- |
| 已观察 | 键盘实际进入且读到了内容 | 可访问性树中存在该节点，且有可访问名称或文本 |
| 页面文本确实没读到 | 页面可见文本中不存在该信息 | 元素不存在或 `innerText` 为空；不是“没找到” |
| 键盘路径进不到 | 元素存在于 DOM 与可访问性树，但焦点走不到 | 焦点巡查形成闭环仍缺该控件，且 DOM 中 `tabIndex >= 0` |
| 当前资料不足以判断 | 来源或发版清单未提供判断依据 | 例如没有该人群/模式的声明，或来源 404 |

去重规则：状态指纹 = 发版 + 模式 + 阶段 + 人群 + 报名表版号 + 帮助层版号 + 帮助层开合 + 预览 + 草稿哈希 + 隐藏人群草稿 + 人工接待提示 + 焦点 + 可见文本哈希。外观相同但保留不同人群草稿的两张页面指纹不同，不会被合并。
